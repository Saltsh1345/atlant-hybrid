# AI-маршрутизация Atlant-Hybrid

## Главный принцип

Один основной агент отвечает за соблюдение MASTER ТЗ и границ текущего этапа. Специализированные агенты получают только узкую задачу и не имеют права самостоятельно расширять объём работ.

Проектные правила не могут технически переключить модель в интерфейсе Cursor. Поэтому:

- основной агент выбирается пользователем в Cursor;
- агент может запускать только подходящий тип специализированного исполнителя;
- конкретная модель подагента не фиксируется без запроса пользователя;
- результат подагента проверяется основным агентом по паспорту этапа;
- Gemini остаётся AI-провайдером самого приложения и не заменяется.

## Маршрутизация по задачам

### Этап 0 — правила и документы

- Основной агент: создание правил и паспортов.
- Explore: только для аудита структуры.
- Внешние изменения запрещены до настройки Google Docs.

### Этап 1 — авторизация и Health

- Основной агент: Next.js и Supabase.
- Explore: проверка существующего Huawei Health перед изменениями.
- Security Review: только по прямой команде пользователя перед фиксацией OAuth.
- Browser-use: только для проверки UI и OAuth после ручной настройки ключей.

### Этап 2 — MediaPipe-сканирование

- Основной агент: интеграция камеры и UI.
- Explore: поиск существующих pose/calibration модулей.
- Отдельная математическая проверка формул углов перед внедрением.
- Browser-use: мобильная проверка камеры после разрешения пользователя.

### Технический подэтап 3D

- Основной агент: R3F, материалы и интерфейс подсветки.
- Упрощённый прототип допустим.
- Финальное анатомическое моделирование в Blender требует отдельного 3D-ассета или ручной работы специалиста.
- Нельзя менять сервисы анализа ради удобства модели.

### Этап 3 — планировщик

- Основной агент: Supabase, UI и серверный вызов существующего Gemini.
- Explore: переиспользование dashboard-компонентов.
- Browser-use: проверка календаря, карточек и мобильной раскладки.

### Этап 4 — Live Scanner

- Основной агент: MediaPipe, VBT, жесты и композиция интерфейса.
- Отдельная проверка производительности.
- Browser-use: камера, жесты и мобильный FPS.
- Физические FMG/EMG-данные не имитируются как реальные.

### Этап 5 — аналитика

- Основной агент: агрегация результатов, Recharts и статичный 3D-атлас.
- Отдельная проверка правил симметрии и рекомендаций.
- Browser-use: 360°-вращение, tooltip и адаптивность.

## Запреты

- Не менять AI-провайдера приложения без команды.
- Не принимать вывод подагента как разрешение менять замороженные файлы.
- Не запускать Bugbot или Security Review без прямого запроса пользователя.
- Не выдавать предположение AI за медицинский диагноз.
- Не продолжать следующий этап после завершения подзадачи.
